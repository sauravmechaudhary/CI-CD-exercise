# Exercise 1 - CI/CD Reflection

I'll choose Python as an example language for this exercise because it has a developed CI/CD ecosystem and is frequently used in backend development.

Common continuous integration (CI) tasks in Python projects, like linting, testing, and building, are usually managed by specific tools. To guarantee code quality and consistent formatting, linting can be done with programs like Pylint, Flake8, or Black. Unit and integrated testing are supported by Pytest, which is frequently used for testing. Poetry and setuptools can be used to manage building and packaging. By ensuring that all developers use the same dependencies and project structure, these technologies help minimise "works on my machine" issues.

Other CI/CD options include GitLab CI/CD, CircleCI, Travis CI, and TeamCity in addition to Jenkins and GitHub Actions. Depending on the requirements of a project, these platforms offer various features, cost alternatives, and levels of modification.

I'd probably pick a cloud-based continuous integration system for a team of six devs. In general, cloud solutions are simpler to install, need less maintenance, and integrate well with present version control systems. Additionally, they allow developers to devote more of their attention to code rather than server administration. The most suitable option, however, depends on a number of variables, including workload, budget, security needs, and whether confidential company data must be kept private.
